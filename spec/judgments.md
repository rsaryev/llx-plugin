# Judgments

Behaviour the kit decides where the official docs and types are silent (docs/SPEC.md). Each entry
names the code that holds it and why. A judgment is never counted as compatibility.

| Where                         | Judgment                                                                                          | Why                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `src/format/names.ts`         | The wording of the "not kebab-case" and "may not contain …" messages                              | The docs name the rules but quote no message for them                                     |
| `src/format/manifest.ts`      | The wording of "Unknown field", type-mismatch and missing-metadata messages                       | The docs say these are reported, not their text                                           |
| `src/format/paths.ts`         | The wording of "must start with ./" and "must be .md files"                                       | The docs state the rule; only the `..` message is quoted, and that one is used verbatim   |
| `src/format/manifest-schema.ts` | `author`, `dependencies` objects and `commands` entries are not strict (unknown keys dropped)   | "Unrecognized fields" lists the strict objects; these are not among them                  |
| `src/format/frontmatter.ts` | A block with no closing `---` is not frontmatter (the whole file is body); the closing marker is the first later line that is only `---`; a leading byte order mark is ignored; an empty block is present with no fields | skills.md fixes only the opening line and the unparseable-YAML case |
| `src/format/frontmatter.ts` | YAML is read with the 1.2 core schema (`yes`/`on` stay strings; a duplicate key does not parse) | The docs list the flag spellings but not the parser |
| `src/format/frontmatter-values.ts` | How a bad value is reported (the wording of each reason), that a number or boolean is read as text, that an enum matches exactly with no case folding, and that blank text is absent | The docs name the accepted spellings, not what happens to the rest |
| `src/format/frontmatter.ts` | A block that parses to a list or a single value is `not-a-table`: the file loads with no fields, like unparseable YAML; `line` and `column` count from the opening `---` as line 1 | The docs name only the unparseable case and send users to the parse error, not where it is |
| `src/format/frontmatter-values.ts` | `readInteger` takes a YAML number or a string of digits that is a safe integer, and reports a value outside `min`/`max` as dropped; `readList` has no default separator mode, each field picks one | The docs name the numeric limits and the list spellings per field, not how a bad one is handled |
| `src/loading/resolve/substitute.ts` | The grammar edges: a reference is `${name}` with no braces inside; a `${VAR:-default}` default ends at the first `}` and nests nothing; no escape; an unknown `${...}` stays as written; a `:-default` after a path variable is ignored; one pass, so a substituted value is never rescanned | mcp.md names `${VAR}` and `${VAR:-default}`, skills.md the single pass; neither gives the edges |
| `src/loading/resolve/substitute.ts` | The wording of the warnings (unset variable, option without a value, undeclared option), and that an unresolved reference stays as written | mcp.md says a missing variable is reported and the text kept, not the words; the docs say nothing for an option without a value |
| `src/loading/resolve/substitute.ts` | `SENSITIVE_PLACEHOLDER`: `[sensitive option KEY]` | manifest-reference says a sensitive value in skill and agent content "becomes a placeholder" and gives no text |
| `src/loading/resolve/user-config.ts` | `userConfigText`: numbers and booleans as `String(value)`, a list joined by commas; a key the manifest does not declare has no value; an option with no value and no default is not exported as `CLAUDE_PLUGIN_OPTION_<KEY>` | The docs show string options only and say "every option" is exported |
| `src/loading/resolve/variables.ts` | `Locations.pluginData` receives the sanitized `<id>` (`pluginDataId`), `pluginRoot` the plugin identifier as the host knows it | The docs define the `<id>` of the data folder; the kit owns that rule so a host only joins it |
| `src/loading/resolve/scope.ts` | The host says whether it is Windows (`SubstitutionScope.windows`); only the three path variables are written with forward slashes, never an option value or `${VAR}`; the process environment keeps native paths | "On Windows, most substituted paths use forward slashes"; the kit cannot tell the platform (L3) and the docs do not say which values are paths |
| `src/loading/resolve/surfaces.ts` | `${VAR}` expands only in MCP `command`, `args`, `env`, `url`, `headers` and in monitor `command`; elsewhere (hooks, LSP, `headersHelper`, content) it is left to the process | mcp.md and components.md (Monitors) give the fields; no other component documents `${VAR}` expansion |
| `src/loading/resolve/substitute.ts` | A field that refuses `${user_config.*}` (shell form, monitor, `headersHelper`) leaves the reference as written and reports nothing; the caller reports the documented error from the template (`referencesUserConfig`) | errors.md quotes one message per surface; the surface's resolver owns it, the substitution only guarantees a value is never put into a shell |
| `src/loading/resolve/surfaces.ts` | `mcp-remote` reads as empty exactly the names mcp.md writes (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `AWS_BEARER_TOKEN_BEDROCK`, `HTTPS_PROXY`, `NPM_TOKEN`); the MCP stream extends the set if the docs name more | The page lists covered names with "such as", so the full set is not published; a credential must never reach a remote server, so the named ones are covered now |
| `src/loading/resolve/data-id.ts` | A letter is `A-Z` or `a-z`: a non-ASCII letter (for example `\u00e9`) in a plugin identifier becomes `-` | manifest-reference says "letters, digits, `_`, or `-`" without saying whether letters are ASCII |
| `src/loading/resolve/exported-environment.ts` | A hook, MCP stdio or LSP process always gets `CLAUDE_PLUGIN_DATA`, so the host is asked to create the data folder for each, referenced or not | The table says these processes receive the variable and the data folder is "created on first reference"; the docs do not say whether exporting counts |
| `src/loading/resolve/scope.ts` | `extra` variables (`CLAUDE_SKILL_DIR`, `CLAUDE_SESSION_ID`, `CLAUDE_EFFORT`) are substituted on every surface, shell forms included, and win over `${VAR}` of the environment | skills.md describes them only for skill content; the kit has one substitution pass and the caller decides what goes into `extra` |
